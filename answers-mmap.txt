内存映射文件，将一个文件的内容映射到程序虚拟地址空间的一段上。

实现系统调用
``` c
void *mmap(void *addr, size_t len, int prot, int flags,
           int fd, off_t offset);
int munmap(void *addr, size_t len);
```
mmap参数:
addr 在此实验中无效，通过内核分配映射的地址。我选择映射地址为页对齐的地址，并且为了防止sbrk堆增长的影响，选择使用最大虚拟地址MAXVA的一半左右作为起始地址。
fd 是映射的文件描述符。
offset 是从文件的offset位置开始映射。
len 可以指定映射的地址范围，如果我们分配了地址addr，那么需要为[addr, addr+len)这一段虚拟地址区间分配物理页。映射的文件从offset与addr一一对应，文件大小size可能与addr+len不一致，当size>addr+len时说明文件没有完全映射完，而size<addr+len时，多余的映射的内存将不会回写到文件中，也就是说文件大小size是固定的。
prot 可以指定映射的内存的读写执行等权限。
falgs 可以指定当前内存是私有的还是共享的，这的私有是指从文件中读取后，对内存的修改最终将不会回写到文件中，因此打开的文件带有的权限与映射的内存权限无关。而共享则需要在unmmap时或程序退出时，将映射的内存写回文件中（文件和内存都有写权限），在此模式下，文件的权限不小于内存的权限，比如内存可写文件只读是不可以的。

我们在每个进程结构体中加入一个结构体数组，每个结构体代表映射了一段内存，数组大小决定了最多可以映射多少段内存。
这个结构体需要记录映射的区间范围，映射文件的指针，回写的偏移量。


munmap参数：
addr 指定从addr虚拟地址开始的内存，长度为len，取消映射。
考虑[addr, addr+len)这段范围包含的所有内存，或者部分内存，我们都将其取消映射，一种特殊情况是，如果需要取消映射的内存严格包含在一段映射的内存中，那么取消映射会分割产生两段内存，这种情况不好维护，不考虑，不予取消映射。
所以如果没有完全取消一段内存，同一段内存可能会取消映射多次，每次取消是前/后部分。
现在需要考虑的就三种情况：
取消映射区间[lva, rva)完全包含了一段映射取区间[l, r)，这种情况，如果需要回写，直接从虚拟内存l开始向inode偏移offset位置写入min(r-l, size-offset)个字节。然后取消映射内存，并且释放进程中的映射结构，文件引用计数减少。
取消映射区间[lva, rva)包含了一段映射取区间[l, r)前半部分，这种情况，实际取消范围是[l, rva)，如果需要回写，从虚拟内存l开始向inode偏移offset位置写入min(rva-l, size-offset)个字节。然后取消部分映射内存，并且更新进程中的映射结构。
取消映射区间[lva, rva)包含了一段映射取区间[l, r)后半部分，这种情况，实际取消范围是[lva, r)，如果需要回写，从虚拟内存lva开始向inode偏移offset+lva-l位置写入min(r-lva, size-offset-lva+l)个字节。然后取消部分映射内存，并且更新进程中的映射结构。

munmap在程序退出时，也需要调用，传入一个足够大的区间，保证进程中所有映射段都被释放，此外文件指针需要减少引用次数。
fork时，进程结构体也需要复制各个映射段，文件指针需要增加引用次数。

由于需要实现懒加载，所以映射实际上只有出现页面中断时，我们才将对应虚拟地址所属页进行映射。并读取文件内容到页中。
对于读一个非法地址会出现0xd中断，向一个非法地址写入出现0xf中断。
处理中断时，先看页面是否已经映射，如果已经映射过，那就不是缺页问题，而是页面权限问题，比如向只读页面写入。

有时候，有些页面还没有访问就进行了unmap，如果需要回写到文件，还需要处理页面不存在的情况，如果页面不存在，那么就直接将写入偏移跳过一页。
